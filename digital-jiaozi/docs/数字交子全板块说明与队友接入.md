## 2. 地图交子、地标收藏与素材

地图交子采用 **2:3 竖版、两列三行**的纪念布局，展示已领取地标及到访日期，点击查看详情。这里的“地图”是旅程纪念排版，不提供 GPS 定位或地图导航。个人本地照片每六张增加一页，接在地标页后。

页面与 Canvas 导出共用布局规则。纪念 PNG 宽 1200 像素，每页高 1800 像素，多页纵向拼接；素材缺失会回退并提示。导出图片不能重新导入为旅程数据。

### 照片打卡

在“地标收藏”选一站，点“拍照打卡 · 收藏交子”，拍照或从相册选择 JPEG/PNG/WebP（≤15 MB），查看预览后确认。首次会收藏交子、点亮地图并 +10 分；重复不奖励，取消不领取。照片在本地校正方向并按完整比例压缩至长边最多 1600 像素，不裁剪、不调用定位/识图/生图服务。它是用户自己的照片打卡记录，不代表已核验地点或消费。

照片 Blob、claim、事件、旅程、钱包和流水使用同一事务，任一保存失败全部回滚，可重试。claim 使用 `source:'photo'` 和 `checkinMediaId`；详情及已保存旅程中可回看，刷新恢复。photo 与宿主 host 同地标互相去重、保留首次来源；旧 demo 记录冲突仍拒绝，不改写原数据。照片打卡与本地照片贴片、AI 作品库独立，不自动创作作品。

## 3. 积分与礼品兑换

现有规则集中在 [rules.ts](../src/config/rules.ts)，活动 ID 为 `six-landmarks-2026-v1`。以下是当前代码口径，本文不修改规则：

- 初始 0 分；同活动内每个地标首次领取奖励 10 分，六款地标奖励合计 60 分。活动方核验的消费积分可另行累计，远端活动账户允许超过 60 分。
- 领取地标、钱包和积分流水在同一事务中保存。同一事件重放、同一地标重复打卡或多标签页并发不会重复奖励。
- 同时保留“累计获得”和“可用余额”；兑换只扣余额，收藏、地图和累计获得保持不变。
- 独立开发演示的本地兑换按 `requestId` 去重并原子扣分，待领取可取消退款一次，模拟领取后不可取消。游客只通过真实 RewardsAdapter 兑换，服务须原子检查积分和库存、生成订单、执行幂等和退款，工作人员核销不向游客开放。
- 本地照片贴片、AI 创作和保存旅程均不增加旅游积分；地标照片打卡按首次每款 10 分奖励。旧升级、旧积分和旧任务不继承。

| 礼品 ID | 当前礼品名称 | 所需积分 |
| --- | --- | --- |
| `gift-charm` | 胸章 / 小挂件 | 20 |
| `gift-magnet` | 普通主题冰箱贴 | 30 |
| `gift-keepsake` | 纪念小物 | 40 |
| `gift-panda` | 熊猫玩偶 | 50 |
| `gift-nfc` | NFC 实体纪念交子冰箱贴 | 60 |

**六款数字地标交子、60 分固定款 NFC 实体礼品、个人 AI 珐琅作品是三套不同内容。** AI 生成不代表兑换成功，也不会替换固定款礼品。当前真实兑换服务、库存、发货和工作人员核销尚未接入；游客可浏览规则但不可提交，不扣本地积分。RewardsAdapter 的完整类型、HTTP 示例、requestId 重试及取消约定见 [宿主接入](integration.md)。远端账户只用于展示，不混写本地钱包；本地记录不能当作服务端可信额度。

## 4. 照片记忆：本地贴片与 AI 创作

照片页默认展示 AI 珐琅创作，下方“本地照片贴片（裁剪 / 滤镜）”默认折叠。两条流程的产物和保存位置不同：

| 对比 | 本地照片贴片 | 个人 AI 珐琅作品 |
| --- | --- | --- |
| 用途 | 给地图、旅程增加个人照片纪念 | 用真实照片生成一张个人珐琅效果图 |
| 操作 | 选照片、调整、命名、保存 | 选照片、点“一键生成珐琅冰箱贴” |
| 处理位置 | 浏览器本地 | 用户点击生成后，由服务端上传到供应商 |
| 结果 | 512×512 PNG | 完整 AI PNG；可另做纪念海报 |
| 保存位置 | 核心照片库、地图及后续保存的旅程 | 独立个人作品库 |
| 对积分影响 | 无 | 无 |

### 本地照片贴片

支持相册/拍照入口、EXIF 方向归一化、真实裁剪、拖动、双指或滑块缩放、90°旋转，以及彩色/单色/线条三种效果。保存的是 PNG Blob，页面预览与保存结果一致，刷新后可恢复。

“彩色”保留照片观感，属于本地滤镜工具，不是 AI 生成结果。没有 AI 配置时仍可手动命名、保存。宿主可选的 `identifyPhoto(blob)` 仅辅助命名，未接入时不显示该辅助按钮，和珐琅生图服务分开配置。

旧工具选好照片后，可以点“用这张照片制作 AI 珐琅冰箱贴”，带入原文件及已有名称；带入本身不会上传或发起生成。

### 一键生成珐琅冰箱贴

游客只需 **上传照片 → 点击一键生成**，不填写类别、主体、标题、地点、年份或背景色。同一次 `gpt-image-2` 图生图请求观察照片并选择主体与配色，没有额外识图调用；不把推测的地点、年份或人物身份当作事实。

AI 使用完整照片副本；方向与海报焦点调整是可选操作，默认不需要展开。只有主动点击生成才上传照片并产生供应商调用。选择文件、切换页面或刷新不会自动发单。

独立作品库保存原文件、方向校正副本、完整生成 PNG、任务元数据及可选海报。可保留草稿、重新打开、下载、刷新恢复。AI 作品不会自动加入地图、地标收藏、积分兑换或旅程快照；可选 `journeyId` 仅作为作品关联字段。

### 动态预览与任务恢复

生成中，主预览和对应作品卡同步显示浅色动态点阵及 **0–95% 的“预计进度”**。此时隐藏原照片、裁切 Canvas 和旧成图，避免观众把原照片当作生成结果。

供应商没有真实进度和中间帧接口，所以动画不代表已经生成了某一部分画面。只有收到真实图片、通过 SHA-256 完整性检查和解码后才显示 100%，短暂停留约 500 毫秒再在原位显示成图。完成后，参考照片收进可选调整区域。

草稿、失败和结果未确认状态使用明确状态卡；作品库只有已完成 AI 图可以充当成品缩略图。刷新后的未确认任务显示静态待确认状态，不自动继续动画或重发。已支持系统“减少动态效果”，卸载时清理计时器。

网络断开、超时或无法验证结果时，界面保守显示结果未确认；这不代表供应商一定没有处理或计费。可主动点“查询本次临时结果”，只读本模块中转缓存。明确确认重新生成才创建新任务，不自动重试付费请求。

### 原图下载与独立纪念海报

生成 PNG 按返回字节完整保存和下载，不自动裁剪、缩放或加字。可另选“制作纪念海报”：人工确认生成图裁切后，本地合成 3:4 海报，上半 AI 图、下半真实照片，各占 50%，图片采用 `contain`，不放大小图。

海报与原图分开保存。调整照片焦点、重做海报或合成失败后重试，无需再次生图。若 AI 成功但本地保存失败，当前页面仍可下载原图，应先下载再离开。生成的是数字效果图，实际制作刀模、材质和生产验收仍由制作方负责。

## 5. 旅程保存与 NFC 打开恢复

每次保存旅程都会创建一个**新的、不可覆盖的快照 ID**，保存当时路线展示字段、到访顺序、地标名称及图片路径、个人本地照片引用。后续继续打卡或再次保存不会覆盖旧纪念；原进行中旅程与保存后的快照是不同记录。

NFC 流程为：

1. 在最终网站、目标手机浏览器中完成打卡及照片纪念，保存旅程。
2. 复制页面生成的专属旅程网址。游客无需填写编号；如需 tagId 映射，由宿主 bindTag 或开发演示技术入口操作。
3. 使用写卡工具把网址作为 URL 写入 NFC 标签。
4. 手机碰标签后由系统打开浏览器，网页读取该浏览器的本地记录并展示旅程。

通用入口示例：`https://example.org/team/digital-jiaozi/#/digital-jiaozi/journey`。这是格式示例，需换成最终长期稳定的 HTTPS 地址。无参数入口恢复最近保存的快照；明确指定但找不到的 `journeyId` 或 `tagId` 显示空状态，不替换成其他旅程。

NFC 只打开网址，不在标签中保存照片或完整路线，不依赖 Web NFC 或微信 SDK。`tagId` 绑定仅存在本机，不能当跨设备身份凭证。

恢复要求**同设备、同浏览器档案、同网站 origin（协议、域名、端口）**。换浏览器、清除网站数据或改部署 origin，不会自动迁移记录；子路径本身不隔离 IndexedDB。无云同步或云备份，PNG 导出也不是数据备份。当前未确定最终公网地址、未写实体标签，桌面恢复已验证，手机实际碰卡待联调。

## 6. 本地启动与配置

当前实现工作区：`D:\Codex\Jiaozi-Trail-impl\digital-jiaozi`；Git 分支：`codex/digital-jiaozi-impl`。`D:\Codex\Jiaozi-Trail` 是参考资料工作区，不要把它误当作本次启动目录。队友克隆后使用自己仓库中的 `digital-jiaozi/` 路径即可。

需要 Node.js **22.13+**。在模块目录安装并启动前端：

```powershell
Set-Location D:\Codex\Jiaozi-Trail-impl\digital-jiaozi
npm ci
npm run dev
```

打开 `http://localhost:5188/#/digital-jiaozi`，确认标题为“数字交子 · 我的旅行记忆”。端口固定为 5188，已占用会报错，不会自动跳到另一个端口；其他项目常用的 5173 不是本模块入口。

AI 功能还需在第二个终端、同一模块目录运行：

```powershell
npm run magnet:server
```

中转监听 `127.0.0.1:5191`，Vite 把 `/api/digital-jiaozi/magnets/` 代理到中转。个人收藏、积分、旅程、本地照片和 AI 草稿不依赖该服务；服务未配置时生成按钮不可用。

配置模板为 [.env.example](../.env.example)。本机已配置忽略的 `.env.magnet.local`，**不要覆盖现有文件**；新环境按模板在服务端配置 `DJ_MAGNET_API_KEY`。服务端显式加载模块配置，已有环境变量优先，也可通过服务端 `DJ_MAGNET_ENV_FILE` 指定配置文件位置。密钥不能使用 `VITE_` 前缀、写入前端、粘入文档或提交 Git。

同一局域网的手机可将 localhost 换为开发电脑 IP，放行开发端口。HTTP 下部分能力有回退，不能代替正式 HTTPS 或真机兼容性验证。不要把临时局域网地址写成正式 NFC 入口。

## 7. 给主站队友的接入方法

### 最小挂载

宿主支持 TypeScript/CSS 时可直接导入源码；以下路径以主站工程能找到 `digital-jiaozi/` 为例：

```ts
import { mountDigitalJiaozi } from './digital-jiaozi/src/module.ts';

const container = document.querySelector<HTMLElement>('#jiaozi');
if (!container) throw new Error('缺少数字交子挂载容器');
const api = await mountDigitalJiaozi(container, {
  routing: 'memory',
  assetBase: '/team/digital-jiaozi/',
  publicBaseUrl: 'https://example.org/team/digital-jiaozi/',
  magnetApiBase: '/api/digital-jiaozi/magnets',
  mode: 'visitor',
});
```

示例网址需替换。`routing: 'memory'` 不读写宿主 hash，宿主通过方法切页；`assetBase` 下要能加载 `assets/landmarks/` 和 `assets/fonts/`。`publicBaseUrl` 指向可真正打开模块的长期入口，恢复本地记录时必须保持同 origin。独立站默认使用 hash 路由。

宿主不直接处理源码时，在本模块执行 `npm run build:module`，使用 `dist-module/digital-jiaozi.js`、`digital-jiaozi.css` 和构建复制的 `assets/`。JS、CSS 和素材都要部署；字体及许可文件一并保留。不要复制 `node_modules/`、`var/` 或 `legacy/` 作为前端模块。

样式采用 `.dj-app` / `.dj-` 前缀。模块底导航固定在视口，宿主应给出完整页面区域，避免两个固定底导航重叠。

### 路线与活动打卡

游客内置照片打卡无需适配器，可直接在独立站或游客 iframe 使用；不会调用商家试玩桥接。下面的 `navigateToCheckin` 为可选的额外活动打卡入口，不控制照片打卡开放。消费奖励仍沿用队友规则，照片来源通知不可当作已核验消费重复发分。

宿主应先建立六个 `placeId` 映射，再通过挂载参数 `landmarks` 注入；也可用双方约定的稳定 `landmarkId` 传入事件。宿主接口形状见 [adapters.ts](../src/adapters.ts)：

| 可选适配器 | 宿主负责返回或执行 |
| --- | --- |
| `getRouteSnapshot()` | 返回实际选择的路线快照，或 `null` |
| `navigateToCheckin(landmark)` | 打开宿主对应地点的打卡页 |
| `navigateToRoute(routeId?)` | 打开宿主路线页 |
| `identifyPhoto(blob)` | 经宿主服务辅助命名，返回 `{ title?: string }`；与珐琅生图区分 |
| `rewards` | 实际活动账户的 load/redeem，可选 cancel；完整协议见 integration.md |

以下为字段示例，`host-route-001`、`host-place-ifs` 和事件 ID 必须由宿主真实数据替换。不要在挂载时无条件执行这段打卡代码，应在宿主确认打卡完成后调用，并处理 Promise 失败：

```ts
const current = await api.getContext(); // 本模块的进行中旅程
await api.setRouteSnapshot(current.id, {
  id: 'host-route-001', title: '实际选中的成都路线', source: 'host',
  places: [{ id: 'host-place-ifs', name: '成都 IFS' }],
});
const result = await api.acceptCheckin({
  eventId: 'checkin-unique-001', // 同一打卡重试时保留同一 ID
  activityId: 'six-landmarks-2026-v1',
  journeyId: current.id,
  routeId: 'host-route-001',
  landmarkId: 'landmark-01', // 或已配置映射的 placeId
  occurredAt: new Date().toISOString(), // 实际接入传打卡发生时间
});
// result: { claim, awarded: 10 | 0, duplicate: boolean }
const saved = await api.saveJourney(current.id, '那次成都旅行');
const journeyUrl = api.getJourneyUrl({ journeyId: saved.id });
await api.bindTag('souvenir-001', saved.id);
api.openJourney({ journeyId: saved.id });
```

`journeyId` 是本模块生成的本地旅程 ID，不能直接使用宿主 `routeId`。传 `routeId` 时，须先设置同 ID 的路线快照；`setRouteSnapshot` 只保存路线，不发奖。保存后的网址必须使用 `saveJourney()` 返回的新 ID。

事件来源由 `acceptCheckin()` 固定为 `host`；独立演示来源为 `demo`。该标记不等于服务端认证，须在宿主验证成功后输入。重复事件内容冲突会报错，换事件 ID 重复打同地标不重新加分；已有历史 demo 同地标时拒绝 SOURCE_CONFLICT，不覆盖或改成真实来源。ID 格式限制及错误处理见 [详细接入说明](integration.md)。

### 公开方法与通知

| 方法 | 用途 |
| --- | --- |
| `getState()` / `getContext()` | 读取档案汇总 / 当前进行中旅程 |
| `getVisitorState()` | 读取排除旧演示奖励的本地投影，不是远端活动账户 |
| `setRouteSnapshot(journeyId, route)` | 保存路线展示快照，允许 `null` |
| `acceptCheckin(input)` | 接收宿主打卡并去重领取 |
| `saveJourney(id, title, route?)` | 创建并返回新的纪念快照 |
| `bindTag(tagId, savedJourneyId)` | 建立本机标签与已保存旅程的关联 |
| `getJourneyUrl({ journeyId?, tagId? })` | 生成旅程/NFC 网址 |
| `navigate(view)` | 切换五个主视图 |
| `openJourney({ journeyId?, tagId? })` | 打开指定纪念或最近保存记录 |
| `openMagnet({ journeyId? })` | 打开 AI 创作，可关联后续新作品 |
| `on(listener)` | 订阅模块通知，返回取消订阅函数 |
| `destroy()` | 离页卸载并清理监听、临时 URL、计时器与数据库连接 |

通知有 `digital-jiaozi:claim` 和 `digital-jiaozi:points`，携带本地 `wallet: { activityId, earned, balance }`，可含 `landmarkId`、`source`（photo/host/demo）。游客通知过滤旧演示奖励，不代表兑换服务余额；宿主积分徽标需要真实额度时应读取活动账户。通过返回的 API 订阅，不向 `window` 广播；通知不能再作为新打卡或消费输入。

```ts
const off = api.on(event => {
  if (event.type === 'digital-jiaozi:points') {
    // 可同步本地收藏积分；真实可兑额度读取活动账户服务。
  }
});
// 宿主离开页面时执行：
off();
api.destroy();
```

## 8. AI 服务与生产部署

服务端代码位于 [server/magnet/](../server/magnet/)。当前适配固定使用 `POST https://api.openai-next.com/v1/images/edits`、模型 `gpt-image-2`，真实 multipart 照片，`n=1`、`1536x2048`、`medium`、PNG。它不是任意模型的通用适配器；更换供应商需重新验证协议。

| 本模块接口 | 行为 |
| --- | --- |
| `GET /api/digital-jiaozi/magnets/status` | 返回是否已配置、模型和超时，不返回密钥 |
| `POST /api/digital-jiaozi/magnets/generate` | 接收 UUID `requestId` 与照片；当前网页使用 `category=auto`、`style=enamel`，不发送手填主体、颜色或标题 |
| `GET /api/digital-jiaozi/magnets/results/:requestId` | 读取本中转临时结果，不调用供应商；进行中 409，缺失/过期 404 |

中转包含文件解码、尺寸检查、参数白名单、单进程上游并发 1、每 IP 最短 10 秒间隔，以及本进程请求去重。成功结果最多缓存 15 分钟，容量压力可提前清理，重启或多实例不共享；这不是供应商任务查询或持久任务队列。默认供应商超时 180 秒，Node 请求额外预留 30 秒。

构建独立站使用 `npm run build`，产物为 `dist/`，默认 base 为 `./`，支持子目录部署。需固定路径时设置 `DJ_BASE=/team/digital-jiaozi/` 后构建。hash 路由不要求服务端为每个子视图 rewrite，但部署目录必须正常返回 `index.html`，不能直接双击 `file://` 文件运行。

生产 AI 需要同时部署 Node 中转，将 `/api/digital-jiaozi/magnets/` 同源反代到 5191，允许至少 16 MiB 请求体、代理超时 330 秒，并禁用 POST 自动重试。仅上传静态 `dist/` 或运行 `npm run preview`（4173）不能提供 AI 生图代理。前后端需一起更新并重启中转。

详细配置和挂载参见 [珐琅模块接入](fridge-magnet-integration.md)，协议、故障状态与缓存参见 [珐琅 API](fridge-magnet-api.md)。当前为单进程受控演示，公开多人服务还需接入账户权限、共享配额和持久任务等能力。

## 9. 数据与源码位置

核心 IndexedDB v2 使用 `digital-jiaozi:personal` 和 `digital-jiaozi:sample`，包含 `meta`、`wallets`、`journeys`、`claims`、`ledger`、`redemptions`、`media`、`photos`、`events`、`tags`、`archives`、`merchantCheckins`。v1 无损升级只新增商家 store 和每日唯一索引，原数据不清空，profile.schema 仍为 1。照片持久化为 Blob，不把临时 `blob:` URL 当成文件。

AI 作品使用独立的 `digital-jiaozi:magnet:personal` 和 `digital-jiaozi:magnet:sample`，通过 `works` 保存图片、任务及作品版本。两个数据体系不自动互导；重置示例只清示例，不清个人档案。旧 `dj:` 设置只读归档，不导入旧积分；不兼容数据库版本会保留数据并报错，不自动删库。旧服务器照片与 SQLite 不自动迁移。

历史个人演示记录不迁库、不删除、不改来源。游客页面和 getVisitorState 显示 host/photo 收藏及对应 earn 流水，本地余额保守取不高于非演示累计与旧余额的值；旧兑换不冒充真实订单，演示记录在折叠区保留。getState 继续返回完整原始记录。游客新快照过滤演示收藏/路线，旧快照带来源警示照常回看，照片与 AI 原图保留；本地照片奖励不自动计入远端可信账户。

已核对 GitHub `origin/main` 的商家试玩积分，保留其配置、每日去重、事务和公开桥接方法；模拟写操作统一限独立演示模式。旧主站只接受 `demo:true/sample:false`，而新版游客为 `false/false`、演示为 `true/true`，必须由队友同步调整主站，不能仅替换构建目录。完整片段与实际验证范围见[商家积分兼容与主站联调](商家积分兼容与主站联调.md)，本轮未修改地图文件。

4. 确认最终 HTTPS 同源入口和 AI 反代配置，再做受控生成验证；不把密钥、私照或生成记录提交仓库。
5. 用目标手机在最终网址保存数据，写入正式 NFC URL，再实际碰卡、关闭重开、检查图片与旅程恢复；换设备不会继承原浏览器档案。
