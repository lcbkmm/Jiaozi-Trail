# 数字交子 · 游客手机网页

**队友先读：[数字交子全板块说明与队友接入](docs/数字交子全板块说明与队友接入.md)**。包含本负责人全部模块的功能、规则、启动、数据、主站接口、部署/NFC、验证记录及待联调事项。

本模块使用独立 Vite + TypeScript 手机网页，默认入口已是游客端。个人旅程、收藏、本地积分记录和照片 Blob 保存在当前浏览器的 IndexedDB；照片打卡、照片创作、纪念导出、旅程保存与本机回看可直接使用。地标收藏支持拍照或相册选图，确认后领取交子、点亮地图并获得首次 10 分。活动到访核验、消费核验和礼品兑换需要团队业务服务；兑换未接入时显示“暂未开放”，不会制造订单或扣分。旧小程序/SQLite 后端与旧积分仅归档在 `legacy/`，不参与当前构建。

2026-11-01：游客入口为 `/#/digital-jiaozi`，开发演示独立为 `/demo.html#/digital-jiaozi`。游客端没有示例领取、模拟核销或标签配置；URL 添加 `sample=1` 不会开启演示权限。演示只使用独立示例库，历史个人档案中的演示来源记录保留但不计作游客收藏；照片、作品和旧快照不删除。接入与部署见 [integration.md](docs/integration.md) 和 [visitor-deployment.md](docs/visitor-deployment.md)。

新增可选的“照片生成珐琅冰箱贴”：使用模块专属 Node 中转真实上传照片至指定供应商，生成原始 PNG 完整保存在本机作品库，可直接下载；上下拼接纪念海报另存。只有用户点生成才上传，不改变旅游积分和地标规则。本地保存不代表照片从不离开设备。

2026-10-31 最新补充：用户提供的六张正式地标票图已接入，编号依票面 CX1001–CX1006 对应 IFS、太古里、九眼桥、大慈寺、水井坊、三圣乡。图片交付后的事实覆盖原改造提示词中“图片未完成、地名未确定”的状态；积分规则仍沿用该提示词。

## 在哪里运行

实际代码：`D:\Codex\Jiaozi-Trail-impl\digital-jiaozi`，分支 `codex/digital-jiaozi-impl`。参考资料仓库 `D:\Codex\Jiaozi-Trail` 保持原样，未覆盖另一窗口文件。所有本轮变更在 `digital-jiaozi/` 内。

使用 Node.js 22.13+：

```powershell
Set-Location D:\Codex\Jiaozi-Trail-impl\digital-jiaozi
npm ci
npm run dev
```

电脑打开 `http://localhost:5188/#/digital-jiaozi`。本模块固定使用 5188，避免与其他 Vite 项目常用的 5173 混淆；启动后请使用终端实际输出的地址，确认页面标题为“数字交子 · 我的旅行记忆”。手机和电脑连接同一局域网，将 localhost 换成开发电脑的局域网 IP；允许本机开发端口通过防火墙。HTTP 局域网预览有相册与拍照文件选择回退，剪贴板及系统拍照能力以手机浏览器支持为准。不要把 LAN 地址当正式 NFC 入口。

## 本期规则

- 六款平等地标票，每款首次打卡 10 分，初始 0，六款地标奖励合计 60 分。按活动+地标去重，事件重放和多标签并发不会重复奖励；活动方核验的消费积分可另行累计，活动账户不限制为 60 分。
- 游客在地标收藏页拍摄或选择一张 JPEG/PNG/WebP 照片，预览后确认打卡；照片完整保留构图，压缩后存本机，在交子详情和已存旅程中可回看。选择或取消文件不发分，保存失败时照片、收藏与积分全部回滚。照片打卡不调用定位、识图或生图服务。
- 同时显示累计获得和可用余额；兑换只消费余额，地图和收藏保持不变，无等级、升级或旧积分任务。
- 礼品规则保持 20/30/40/50/60 分。60 分是固定款 NFC 实体纪念交子冰箱贴，不是升级形态；开放情况、额度及订单以活动服务返回为准。
- 游客兑换与取消只有接入真实服务后开放；前端不执行工作人员核销。开发演示可模拟扣分、待领取取消与确认领取，结果只保存在示例库。
- 照片上传、裁剪、旋转、彩色/单色/线条处理在本地完成，成品以 PNG Blob 保存，不奖励积分。无 AI 配置时手动命名可完整使用。
- 个人珐琅作品独立于六款地标和固定款 NFC 纪念交子；可保存草稿、生成原图、另做3:4海报、刷新恢复和下载。AI费用由供应商产生，与旅游积分无关。
- 照片打卡使用 `source:'photo'`，宿主活动打卡使用 `host`，开发演示使用 `demo`；同地标 photo/host 互相去重，不重复奖励或改写原来源。没有实现真实 GPS 认证、可信积分、工作人员核销或跨设备恢复。

已核对 GitHub `origin/main` 的商家积分实现，保留商家配置、每日去重、事务记账及地图桥接方法。当前上游是 `demoCheckin` 试玩加分，不能视为真实消费核验；模拟行为仅在独立演示库运行。数据库无损升至 v2，保留原始记录。主站旧桥接写死旧模式，需要队友按[商家积分兼容与主站联调](docs/商家积分兼容与主站联调.md)同步调整入口与状态判断；本轮没有修改主站，也未声称整站已联调通过。

## 生产构建与静态部署

```powershell
npm run check
npm test
npm run test:magnet-server
npm run build
npm run build:module
npm run test:browser
npm run preview
```

`dist/` 是独立站点，`index.html` 默认游客入口、`demo.html` 为独立开发演示入口；正式部署可不发布 `demo.html`，保留公共 assets。`dist-module/` 是给队友的 ES 模块、CSS 和静态素材。构建产物不进 Git。默认 Vite base 为 `./`，生产浏览器测试实际部署在 `/preview/` 子路径下并直接打开深链接。

若部署目标要求固定绝对 base：

```powershell
$env:DJ_BASE = '/team/digital-jiaozi/'
npm run build
Remove-Item Env:DJ_BASE
```

路由位于 hash 内，静态服务器只需正常返回该部署目录的 `index.html`，无需为 hash 路由设置服务器 rewrite。不支持直接双击本地 HTML 的 file 协议。

## 珐琅冰箱贴运行与三步演示

当前实现工程已从用户指定文件安全复制配置到 `D:\Codex\Jiaozi-Trail-impl\digital-jiaozi\.env.magnet.local`。服务端按源码相对路径**显式加载**它，已有环境变量优先；不需要重新填写或覆盖现有文件。全新部署时参照 `.env.example`，仅在服务端设置 `DJ_MAGNET_API_KEY`；不要使用 `VITE_` 前缀。指定其他配置文件用服务端 `DJ_MAGNET_ENV_FILE`，不把密钥写入启动命令。

在模块目录的两个终端分别运行：

```powershell
npm run magnet:server
```

```powershell
npm run dev
```

前端 `http://localhost:5188/#/digital-jiaozi/photos`，中转 `http://127.0.0.1:5191`。Vite将专属 `/api/digital-jiaozi/magnets/` 代理到中转。首次看到“服务已连接”后：

照片页默认展示 **AI 照片创作 → 照片生成珐琅冰箱贴**。最新流程为“上传照片 → 一键生成”，不再显示或要求填写类别、主体描述、标题、地点、年份或背景色。现有 `gpt-image-2` 在同一次图生图请求中观察真实照片、选择主体类别及协调配色，没有新增识图接口。地点、年份和人物身份不自动猜测为事实。

下方“本地照片贴片（裁剪 / 滤镜）”默认折叠，只做本地处理。已在旧工具选图时，可点“用这张照片制作 AI 珐琅冰箱贴”，带入原文件及已有名称后直接生成，无需重新填写。带入本身不调用 AI。辅助命名只在宿主接入后显示，与珐琅生图服务分别配置。

1. 选相册或拍照文件，页面显示完整照片；无需填写表单。方向和海报3:2裁切藏于可选调整中，默认无需操作；AI始终使用完整照片副本。
2. 点“一键生成珐琅冰箱贴”，主预览和对应作品卡显示浅色点阵波动与百分比。图片校验完成后显示100%，再在预览位置切换到完整生成原图，可直接下载。刷新不会重新发单，未知任务可点“查询本次临时结果”读取中转15分钟缓存。
3. 可选“制作纪念海报”，人工调整生成图四边范围并确认主体完整，再合成、下载。调整照片焦点后只需本地重新合成，不必再次生图。重新打开作品库可恢复原图和海报；已有作品的旧标题保留，新作品无需填写标题。

供应商目前只返回最终图片，没有中间帧或进度接口。界面明确标注“预计进度”，从0开始、等待时最多95%，只有真实图片通过完整性及解码检查后才到100%。它是等待动画，不是生成中间图。草稿、失败及结果未确认均显示状态卡，不再用上传照片充当作品缩略图；生成中隐藏参考照片、裁切预览和上次成图，成功后参考照片收进可选调整。刷新后未确认任务显示静态“等待确认结果”，不继续模拟进度或自动重发。支持系统“减少动态效果”设置。

此前的手动描述版本已用一张程序绘制场景完成一次真实网页调用，返回1536×2048 PNG，原图下载及刷新恢复均逐字节一致；流程耗时约32.7秒。当前游客端、一键自动模式及动态预览通过假上游协议、31项浏览器回归与本机页面验证，未再次付费测试生成效果。测试脚本 `scripts/verify-magnet-real.mjs` 已适配一键流程，不属于普通回归，已有调用记录会拒绝重跑，避免重复付费。

线上部署需同时提供静态前端与 Node 中转。将上述API前缀同源反代到5191，允许至少16 MiB请求体，代理超时330秒并禁用POST自动重试；Node默认请求超时210秒。单独上传 `dist/` 或运行静态 `preview` 不能提供在线AI生成。Serverless须满足原始multipart、sharp依赖、长超时和足够大的响应限制。当前为单进程受控演示，未部署公网；挂载代码、跨域和多实例限制见 `docs/fridge-magnet-integration.md`。

## NFC 最终网址与保存

以下域名只是格式示例，应替换为实际长期稳定的 HTTPS 部署地址：

- 通用入口：`https://example.org/team/digital-jiaozi/#/digital-jiaozi/journey`
- 专属入口：在“旅程纪念”保存后复制页面生成的 `journeyId` 网址。
- 本机标签：开发演示页提供 tagId 配置；宿主可通过 `bindTag()` 绑定个人已存快照。游客只需保存和复制网址，无需手填编号。绑定只存在当前浏览器。

把最终网址作为 URL 写入 NFC 标签。NFC 只让系统打开网址，网页不读取 NFC 硬件，也不需要 Web NFC/微信 SDK。标签不包含照片、完整路线或密钥。

每次保存创建独立旅程快照，保留当时路线、到访顺序、地标展示字段和照片引用；继续领取或再保存不会覆盖旧快照和旧 journeyId。无参数入口恢复最近保存快照。指定不存在的 journeyId/tagId 会显示“当前浏览器暂无这段旅程”，不会替换成别的记录。

必须使用同一手机、同一浏览器/用户配置、同一网站 origin。更换域名、协议、端口、浏览器或清除网站数据不会自动恢复。网站子路径不隔离 IndexedDB；独立示例使用另一数据库，重置示例不清个人记录。浏览器可能因清理或空间不足移除本地记录；本模块没有云备份。导出的纪念 PNG 是图片，不是可重新导入的旅程备份。

**本轮验证了桌面 Edge 打开同一 URL 恢复记录；尚未实测手机碰 NFC、手机系统实际拍照或 iOS Safari。**

## 游客体验与开发演示

游客从默认首页查看空白地图、六张正式票面，在“地标收藏”拍照打卡，或进入“照片记忆”主动生成 AI 作品、展开本地贴片工具。照片打卡首次奖励每地标 10 分，无需宿主接口；作品库、完整原图下载、纪念海报、地图导出与旅程保存均可用。保存后复制纪念网址，再在同一浏览器打开可回看地标及打卡照片。缺少真实兑换服务时礼品不可兑换、不扣分。

需要向评委模拟六地标收藏与礼品流程时，单独打开 `http://localhost:5188/demo.html#/digital-jiaozi`，顶部持续标明“开发演示”。这里可演示领取六票、兑换与取消、选择示例路线、保存和标签绑定；使用示例库，不能充当游客真实订单。重置仅影响示例档案和示例作品库，返回游客入口不会带入模拟积分。

活动核验、路线和礼品兑换需队友按 [宿主接口](docs/integration.md) 接入，照片打卡和个人纪念可独立使用；目标手机和正式 HTTPS 域名下的 NFC 仍需验收。
