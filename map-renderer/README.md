# 春熙路三维街区

独立 Web 演示，不依赖微信页面。主入口 `baidu-map.html` 目前使用本地 Three.js，根据真实地理快照构建楼体和街道。文件名保留旧预览地址；它已经不再是百度 SDK 底图，也不是放大一张静态图片。

## 运行与操作

安装 Python 3.10+ 后，在仓库根目录运行：

```powershell
.\start-preview.ps1
```

启动器先对入口做 HTTP 检查，复用已有服务，或在后台启动项目预览服务并检查就绪状态。打开 [春熙路街区](http://127.0.0.1:8765/baidu-map.html)。可用 `-Port 8766` 指定其他端口，但浏览器个人数据按来源隔离，切换端口不会自动迁移。后台服务不会因启动脚本返回而停止；停止服务进程或重启机器后需重新运行启动器。手动以前台方式运行 `python map-renderer/scripts/serve.py` 时，关闭对应终端也会停止服务。不要另开普通 `http.server`，它不提供路线工坊所需的同源代理。

Three.js 已保存在 `assets/vendor/`，主场景无需 npm。完整数字交子首次构建和路线工坊后端依赖见后文。需要浏览器支持 WebGL2；图形初始化失败时页面会显示原因与二维备选入口。主场景不请求设备定位，也不需要在线地图 Key。

| 操作 | 效果 |
| --- | --- |
| 左键拖动 / 单指拖动 | 在当前春熙路板块内平移 |
| 右键拖动 / 双指旋转 | 转动三维视角 |
| 滚轮 / 双指缩放 | 相机靠近，逐渐显示店铺细节 |
| 向前漫游、WASD / 方向键 | 沿当前视角推进或侧移 |
| 位置核对 | 正北、正交俯视，显示原始建筑地面轮廓与道路名称 |
| 点击楼体或地点 | 查看名称、原始高度资料、坐标和来源链接 |
| 探索路线 | 模拟人物沿缓存的真实步行道路段前进 |
| 点亮地点 | 留下金色探索标记，再次巡航时略过该地点 |
| 路线工坊 | 按时间、预算和兴趣规划，预览、保存并调整完整行程 |
| 我的交子 | 打开完整数字交子模块，关闭后保留原页面和照片编辑状态 |
| 个人名片 | 打开旅人装扮、统一交子钱包、到访记录与礼品兑换 |
| 街角有交子 | 查看体验站，明确确认后模拟商家每日发放 |
| 探索工具 / 发现地点旁的箭头 | 分别展开或收纳右侧工具、右下角地点分类，刷新后记住选择 |

个人名片固定在左下角。工具与分类使用统一的浅色浮层、线条图标和选中状态；小屏或矮横屏首次打开默认收纳。折叠只改变按钮的可见性，不清空筛选、不关闭地点结果，也不中断正在进行的模拟漫游。

固定人物用于测试。路线约 590 米，以 6m/s 模拟移动，不表示实际步行时间或实时导航。画质选项控制像素比例和阴影；细节按空间分块在近处显示。尚未测量用户设备上的帧率。

鸟瞰和前向漫游已提高相机高度与俯视角。相机每帧检查完整移动路径及近裁切面大小，遇到楼墙沿墙滑动，同时平移相机和观察目标，避免左右平移后被旧目标拉回楼内；同时避让屋顶与设备，建筑院落和明确标注底高的架空通道保留通行空间。远距离概览还会按场景安全间距动态调整渲染近裁切面，改善缩小后平移时的深度精度；几何碰撞仍使用独立的保守距离。相关计算回归不能替代实际 WebGL 画面的穿模验收。

## 点亮与探索巡航

点击地点资料中的“点亮”后，地点标签变为金色，真实坐标上增加金环和菱形标记，街区探索进度同步更新。记录保存在当前浏览器的本地存储，刷新后保留；它是地图探索收藏，不会自动打卡、发积分或完成路线工坊中的行程进度。

“探索路线”默认开启发现停靠：只从真实步行线附近 32 米内选择发现点，相邻停靠点至少相隔 25 米，优先采用真实地点。未点亮地点会暂停巡航并打开资料；可点亮后继续，也可直接继续，同一轮不会反复停靠。已点亮地点在以后巡航时直接略过。“下一处未探索”定位尚未点亮的沿途地点，不会瞬移人物。关闭“发现未点亮地点时停靠”即可连续巡航。

## 旅人、钱包与游戏流程

个人名片打开“我的旅人、交子钱包、到访记录、旅途礼品”四个页签。“我的装扮”可修改昵称、短发/齐颈发型和角色配色，也可通过摄像头或上传照片制作头像。三维旅人使用平滑曲面、衣领、口袋、背包和鞋带，闲置和行走时有不同动作。

照片仅在本机完成裁切、平滑和简化色阶，应用至预设三维卡通角色的脸部贴图；编辑器展示的是二维头像与配色预览，应用后到地图查看立体角色。支持 JPG/PNG/WebP，单张不超过 12 MB、4000 万像素；只保存处理后的小头像，未接入 AI 生成、面部识别或单照三维重建。摄像头需要浏览器许可；无法拍照时可以上传。取消不会应用草稿，关闭后停止摄像头。

“街角有交子”把 IFS、太古里西入口、四川特产和烤匠 IFS 的真实地点作为体验站。每站按北京时间每日可明确确认一次试玩发放，入账 10 枚交子，并保留到访与流水。它们是测试入口，不代表已合作商家或真实到店验证。地图、个人中心和完整数字交子都读取同一个数字交子 IndexedDB 钱包；地标收藏、商家试玩、兑换、取消退回不会分别计分。

推荐流程：在路线工坊规划并选择路线 → 在地图查看板块内路段 → 开始并按实际测试情况确认行程进度 → 在体验站明确确认试玩发放 → 查看钱包与到访 → 兑换礼品或保存旅程纪念。地图漫游、点亮收藏、行程进度和商家发放互相独立；移动小人或点亮地点不会自动完成打卡、进度或奖励。礼品兑换先确认扣款，可试玩领取或取消待领取记录并退回同一钱包；目前无真实库存、配送、商家结算或正式核销。

完整交子模块仍保留自己的全部入口。流程、账本约束与本机数据说明见 [游戏闭环与个人中心](docs/gameplay-integration.md)。

## 画面与建模

当前参考用户提供的晴日动画城市画面，从立面构图、屋顶形体和光照关系整体调整。楼体以完整的大墙面、稀疏窗组、带状玻璃和安静侧墙构成，不再每隔固定米数平铺窗格。`game-map-art.mjs` 根据楼高、墙面比例和建筑类型选择 64 种整墙构图，共用一张 4096px 图集；每个原始墙面使用一个独立的图集区域，带内缩边距并禁用重复寻址。近处窗玻璃、窗台另有独立几何，不以放大图集代替细节。

主要楼体表面使用 MeshStandardMaterial 的连续柔和光照，取代原先 MeshToonMaterial 的分段明暗；圆角、连续法线、粗糙度和环境光共同形成平滑的受光过渡，减少方块和硬色阶的观感。场景配有偏冷的环境光、浅灰蓝天空、柔边云层与暖灰地平线。天空下半球、薄雾和页面背景使用一致的暖灰过渡，减轻板块后方大片饱和蓝色的观感；保留源数据中的真实小池塘。现代屋顶取消重复纹理线，加入常驻女儿墙、轻屋沿线和少量退台设备；设备放置会检查院落及轮廓边界。店铺雨棚、橱窗集中在距道路较近的最多两面外墙，避免每个墙边都堆满重复小构件。

街道先合并连续的道路面，再划分车道、步行区、路缘、地表与路线标记，避免交叉口各段重复铺面。道路面根据落地建筑的真实轮廓和板块边界裁切，保留院落；明确架空的楼体不会挖空下方道路。路缘只沿完整路网外边界生成，不横穿路口。桥、隧道、室内及屋顶道路不会压平到地面。当前快照使用 198 条地面道路，排除 22 条非地面道路。

相邻或重叠建筑只生成外露墙面及屋顶，保留高度差和架空空间；源轮廓中零面积的回折不生成假墙。圆角向真实轮廓内部收缩，狭窄轮廓和院落不使用会填满开口的倒角。窗台、雨棚、招牌和屋顶设备都检查完整旋转范围与邻楼、院落及屋面支撑，避免装饰伸入其他楼体。

地图外以低于街区的分层台地、远处云团和暖色地平线衔接，作为游戏章节的边界。它们不表示真实街区或道路，位置核对模式会隐藏这些装饰。

现代楼体保留小幅圆角、倒角和连续法线，雨棚使用曲线几何。精细模式开启抗锯齿与动态聚焦阴影；纹理使用线性过滤、mipmap 和各向异性过滤。新造型与灯光仍是程序化动画美术表现，不是对参考图片逐栋复制，也不将其虚构地形、建筑或角色搬到真实春熙路。

当前快照中有 427 栋楼体、52 栋有名称。楼体来自 OSM 地理轮廓，院落保留开口；门窗、招牌、橱窗和雨棚为程序化美术表现，并不代表实拍或建筑设计资料。仅对数据中标记坡屋顶的建筑使用坡屋顶表现。现代商场保留现代形体，不沿商圈随意散布树木。

圆角只应用于三维美术楼体，幅度小于一米；正北核对模式仍显示未经圆角的原始平面轮廓。超过 35 米的楼高在画面中压缩，最高显示 110 米；详情保留源数据的原始高度及估算状态。缺失高度时采用 12 米示意楼体。尚未制作专属 IFS 熊猫或完整的地标精细模型，外观不等同参考插画。

## 地理位置与范围

场景统一使用 WGS84；东为 +X、北为 −Z，单位为米。OSM 提供道路与建筑轮廓；百度地点原始 BD09 坐标转换至 WGS84，同时保留原坐标供点击核对。POI 可表示入口、地铁或商家，不应直接当成楼宇中心。同名地点按来源 ID 分别保留。

当前范围：经度 `104.0702205–104.0806634`，纬度 `30.6547945–30.6637776`，约 1km²。它只覆盖太古里西入口，未覆盖完整太古里与大慈寺。范围外数据不会被随意放入当前板块。参考插画的建筑排列是艺术构图，不用它调整真实道路或地标的位置。未经核实的熊猫装饰已移除。

“位置核对”切换为正北正交投影，消除倾斜视角中楼顶与地面之间的视差；地点标记尖端指向原始地面坐标。比例尺按当前相机射线计算；透视模式的比例尺只代表画面中心。

```powershell
python map-renderer/scripts/audit_geography.py
# 可选：使用已配置的百度服务端 AK 对比官方正向坐标转换
python map-renderer/scripts/audit_geography.py --baidu-verify
```

审计报告保存到 `output/geography.audit.json`。当前已核对 684 个 OSM 要素与原始下载快照一致；3 个地点的官方正向转换对照约为 0.70 米。这证明保存和坐标转换链的一致性，不代表实地测量精度，也不能排除源数据缺失或过时。

## 数据准备

已有 `output/scene.geojson` 时可直接运行。重新下载需要联网；百度地点可选：

```powershell
python map-renderer/scripts/fetch_scene.py
# 添加百度地点（读取本地 .env 中的 BAIDU_MAP_AK）
python map-renderer/scripts/fetch_scene.py --baidu-poi
```

生成目录 `output/` 和本地 `.env` 已忽略 Git。`scene.geojson` 保存统一地理数据；`overpass.snapshot.json` 保存 OSM 原始响应；`scene.manifest.json` 记录范围、下载时间和转换说明。`output/game/route.preview.json` 是已有模拟路线，重新下载不同区域后需要重新生成或移除，控制器会拒绝区域外路线。

道路拓扑可提前计算，避免每次打开页面重复执行多边形运算：

```powershell
node map-renderer/scripts/precompute_streets.mjs
```

生成 `output/game/street-topology.json`。页面会核对版本及源数据 SHA-256 签名，数据变化后自动回退到现场生成；更新场景或路线后建议重新执行预计算命令。

## 完整数字交子

地图通过同源、常驻 iframe 接入 `digital-jiaozi/` 的完整正式构建，保留我的交子、地标收藏、积分兑换、旅程纪念、照片记忆五个视图及六款票图。原有示例/个人档案、领取与积分流水、兑换和退分、照片裁剪/旋转/效果/PNG 导出、旅程快照、NFC 网址及本机标签绑定继续由原模块维护。打开时暂停地图，关闭后保留未完成编辑；地图模拟漫游不自动记录为正式打卡。

初次构建先在 `digital-jiaozi/` 执行 `npm ci`，随后在仓库根目录运行：

```powershell
node map-renderer/scripts/build_jiaozi.mjs
```

地图内点击“我的交子”即可进入。IFS 和太古里西入口可以返回地图定位；其余四个地标保留交子功能，但不会被虚构在春熙路板块内。已有其他旅程不会错误打开成春熙路缓存路线。数据按同源 IndexedDB 保存，不同端口的数据不会自动迁移。完整说明见 [数字交子接入说明](docs/digital-jiaozi-integration.md)。

## 完整路线工坊

“路线工坊”接入 `module-a/backend` 原有业务：时间、预算、步行、排队、缓冲、兴趣、必去和排除条件；最多三种去重策略；地点、活动和福利；保存、收藏、开始和历史；位置确认、演示状态变更、连续完成进度、风险评估、剩余行程重排及差异确认。对话、澄清、工具轨迹和待确认方案保留原接口。

未配置语言模型时，“整理我的想法”仍可用本地明确规则把简单表达整理成条件，例如“预算150元，逛两小时，保留IFS，不吃火锅，少走路，步行上限2公里，排队不超过10分钟”。先展示改动，确认后才填入表单，还需手动生成方案；遇到未知地点、饮食过敏、无障碍或其他无法识别的要求，会整段阻止应用并提示使用表单，不会悄悄省略。它不是 AI 自由对话；原模型接口未配置时仍明确返回不可用，配置模型后可使用原有结构化对话。主题入口仅预填条件，不会自动规划、保存或开始行程。

保存的真实行程可以带入交子旅程纪念，再返回对应路线。地图内预览使用百度真实步行折线，先从 GCJ02 转为 WGS84；路线站点编号与板块出口可点击。跨出板块再进入的路段分别绘制，不连接成虚假直线；板块外地点保留真实位置，完整资料在工坊中查看。巡航只模拟下拉框所选的一段连续板块内步行线，不冒充完整路线导航。

预览服务首次请求时自动启动模块 A 的独立本机进程。现有 9 个地点和 72 条有向步行路段已有真实缓存，日常规划无需重复请求地图服务。依赖、配置、坐标和全部能力说明见 [路线模块接入说明](docs/module-a-integration.md)。营业时间、排队、活动和福利属于演示配置。
