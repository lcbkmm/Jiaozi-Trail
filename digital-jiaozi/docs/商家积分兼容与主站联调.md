# 商家积分兼容与主站联调

2026-11-01。本轮已只读检查 GitHub `lcbkmm/Jiaozi-Trail` 的 `origin/main`（`ca737bc`，商家集成提交 `93b7fe2`），未合并主分支。以下主站片段由队友审阅后修改对应文件，本轮全部改动限 `digital-jiaozi/`，通过 `codex/digital-jiaozi-impl` 分支交接。

## 已保留的模块行为

- 商家目录 `Merchant`、`configureMerchants()`、`getPlayerState()`、`demoCheckin()`、`redeem()`、`cancelRedemption()`、`receiveDemoRedemption()`、`subscribe()` 及同源 `jiaozi-map:v1` 桥接命令保留。
- 商家试玩按活动 + 商家 + 上海时区日期每日只奖励 10 分；重放、并发、失败原子性保持，不产生地标交子或地图印记。此数值沿用队友实现，没有另设真实消费奖励规则。
- 核心数据库与队友一致为 v2；v1 只新增 `merchantCheckins` 和唯一索引，不删除旧钱包、票图、照片、作品或旅程。商家试玩记录在 `getState()` 保留。
- 新版模拟写操作只允许显式 demo 模式，使用示例库。旧个人库中的试玩来源记录保留但不计作真实到访/真实消费。游客模式不能调用模拟发分、兑换、取消或核销方法。
- 六款地标首次各 10 分，合计 60 分；不是活动账户总上限。真实活动服务可返回叠加消费奖励后的更高积分，前端校验非负安全整数且可用不超过累计。

上游目前通过 `demoCheckin({source:'demo'})` 发放试玩积分，没有找到真实消费订单核验、可信积分账本或工作人员核销服务。因此不能把“点击商家打卡”改名后当成真实消费成功。

## 主站必须同步的入口与模式

上游 `map-renderer/game-map-jiaozi.mjs` 当前固定加载 `index.html`，并只接受 `sample !== true && demo === true`，同时忽略示例库钱包。新版状态如下：

| 模式 | 入口 | demo | sample | 数据 |
| --- | --- | --- | --- | --- |
| 游客 | index.html | false | false | 个人照片打卡及首次地标奖励；商家消费需活动服务核验 |
| 开发演示 | demo.html | true | true | 独立示例库；可模拟商家积分、兑换 |

**旧过滤器会拒绝这两种新状态。只改 iframe 为 demo.html 也不够。** 不要通过改回 `sample:false`、游客设 `demo:true` 或把示例钱包写入个人库规避问题。

队友应在 `setupMapJiaozi` 现有参数中增加 `mode = 'visitor'`，保留其他参数；在函数内使用：

```js
if (!['visitor', 'demo'].includes(mode)) throw new Error('未知的交子模式');
const isDemo = mode === 'demo';
const source = new URL(
  `./assets/digital-jiaozi/${isDemo ? 'demo' : 'index'}.html#/digital-jiaozi`,
  doc.baseURI
);
const isPlayerState = state => state &&
  state.demo === isDemo && state.sample === isDemo &&
  Number.isSafeInteger(state.wallet?.balance) && state.wallet.balance >= 0;
```

替换旧 `source` 和 `isPlayerState` 定义；保留同源与配对 window 校验、请求排序、防旧响应覆盖、加载/错误及关闭处理。`updateWallet` 的示例库过滤和徽标改为：

```js
const updateWallet = message => {
  const balance = message.wallet?.balance;
  if (!Number.isSafeInteger(balance) || balance < 0 || message.sample !== isDemo) return;
  const label = `${balance} 交子${isDemo ? ' · 试玩' : ''}`;
  badge.textContent = label;
  entry.setAttribute('aria-label', `打开我的交子，${label}`);
};
```

把 `resolveState` 中“无效的试玩钱包状态”改为“交子档案模式或钱包状态不匹配”。在现有 `command` 调用 `initialize()` 前加模式保护：

```js
const demoWrites = new Set([
  'demo-checkin', 'redeem', 'cancel-redemption', 'receive-demo-redemption'
]);
async function command(action, payload) {
  if (!isDemo && demoWrites.has(action)) {
    throw new Error('此操作仅供开发演示，游客积分以活动方核验结果为准。');
  }
  await initialize();
  return rpc(action, payload);
}
```

`redeem` 等旧桥接命令是本地试玩命令，不能用于真实游客兑换。游客真实兑换通过下文活动账户适配器，不可删除模式保护来打通。

主站现有商家面板仍为试玩时，调用方须显式 `setupMapJiaozi({ ...原参数, mode:'demo' })`，并持续标注试玩；其状态和操作均使用示例库。游客主站选择 `mode:'visitor'`，并关闭模拟发放/模拟核销入口。两者不能在同一个桥接实例中切换。不要为演示清空个人数据。

游客 iframe 的地标收藏页现已内置照片打卡，不依赖 `demo-checkin` 命令或 `navigateToCheckin`。拍照/选图并确认后，按六地标首次各 10 分保存本地照片、交子和积分，重复不发奖；来源为 `photo`，与活动打卡 `host` 互相去重并保留最早来源。照片不作定位、地点识别或消费核验，不调用生图。宿主收到照片打卡的钱包变化或 `source:'photo'` 通知时，只刷新展示，不应再当成消费订单、调用试玩加分或重复发放地标奖励。远端活动账户与本地钱包仍分开。

## 真实消费与兑换接入

目前模块默认 iframe 只接通读取、路线/地点跳转和开发试玩，不提供凭浏览器消息认定真实消费的命令。正式消费奖励应先由活动服务校验，再通过 `RewardsAdapter.load()` 返回统一活动账户；前端不另算消费奖励，也不向本地钱包重复加同一笔分。

推荐队友在游客主站通过 `mountDigitalJiaozi(..., {mode:'visitor', routing:'memory', adapters:{rewards,...}})` 接入，完整类型及 HTTP 示例见 [integration.md](integration.md)。如继续使用 iframe，需另行增加活动账户适配桥接及身份协议；不能把当前试玩 RPC 当成已完成的正式接口。

待队友确认：

1. 消费核验来源：活动身份、商家稳定 ID、消费订单/核验事件 ID、活动 ID、核验时间及防重复依据。消费金额与奖励规则由活动方确认后实现，本轮未变更。
2. 统一账户返回：累计获得、当前可用、开放礼品和真实订单/领取凭证；包含消费积分，不能仅用最多 60 的地标钱包覆盖。
3. 兑换原子扣分、库存、幂等 requestId、取消退款和工作人员核销；游客仅看服务返回结果。
4. 路线快照的 `source`：游客实际路线应由主站标记 `host`；目前地图缓存试玩路线为 `demo`，不会自动转成游客真实旅程。

## 已验证与未验证的边界

业务测试覆盖商家多连接并发、同日去重、上海时区换日、事件冲突、原子回滚、钱包超过 60、v1 无损迁移及旧试玩来源过滤。

浏览器 `merchant-bridge.spec.ts` 使用测试专用父页面验证新版生产 iframe：游客拒绝试玩且不更改路线、返回地图与地点跳转、演示商家加分/去重/兑换退款/刷新恢复、个人库隔离；测试活动账户超过 60 后可以显示与兑换。

这些是模块和桥接协议验证；测试父页面没有使用上游旧模式过滤器。本文主站片段尚未应用，**没有执行主站整站构建或完成真实消费联调**。队友修改后需要验证地图徽标、商家面板、重复领取、跨入口钱包一致性与返回地图；再执行主站自己的构建和测试。

本地游客入口已独立运行，当前无需修改主站就可体验照片打卡、地标首次奖励、照片创作、作品库和旅程纪念。本机预览继续可用；队友 fetch 模块分支后审阅集成。
