# 微信小程序图片清单与生图提示词

项目：Jiaozi-Trail 数字交子模块

交付平台：微信小程序。

用途：供用户复制提示词到生图模型，生成小程序所需的设计参考和图片素材。本文只提供清单、提示词与接入规格，尚未生成图片。

## 一 生成范围与统一风格

完整清单共 39 张：8 张 UI 与风格参考图，31 张素材或实体卡设计源图。覆盖当前数字交子模块，不包含其他成员负责的完整路线地图、餐厅数据库图片或全项目页面设计。

每个编号生成一张独立图片。UI 参考图用于指导开发排版；实际运行时使用独立的交子底图、印章、商品图和插画，小程序文字、按钮、进度条等由代码绘制。

建议风格为“成都旅行手账与现代交子票面”：暖纸色背景、朱红印章、墨色文字、少量竹青与柔和金色。整体轻盈清楚，有成都文化记忆，适合年轻用户的手机界面。

建议色板：暖纸色 `#F8F4E9`，朱红 `#B83A32`，墨色 `#2B2926`，竹青 `#496C5C`，柔和金色 `#B7985A`。色值用于统一方向，最终准确的文字与交互颜色由开发代码指定。

通用要求：

- 装饰素材不生成中文标题、积分、序号、按钮、二维码或水印；这些在小程序中真实绘制。
- UI 参考图可以有指定中文，以表现层级；若模型出现错字，不把参考图中的文字直接用于产品。
- 所有阶段的数字交子使用同一比例、外轮廓和留白区域；地点章使用同一圆章语言。
- 标注透明背景的素材需要真正的 PNG Alpha；没有透明输出能力时，生成无阴影的纯白背景，后续抠图。不要把灰白棋盘格画进图里，也不要仅通过修改文件扩展名伪装透明。
- 下列尺寸是期望交付尺寸。模型不支持时，优先选择相同比例的原生尺寸；后处理保持比例，不拉伸。
- 原始大图保存在 `D:\Codex\Jiaozi-Trail\digital-jiaozi\assets-source\`，按清单中的相对路径分类。开发时另行压缩并导出运行素材。

## 三 生成顺序与操作方法

1. 先生成 B01，确定交子母版。可同时生成 A02，确定主页面的视觉方向。
2. 把确认后的 B01 作为参考或编辑对象，生成 B02、B03、B04，保留相同位置、轮廓和留白。
3. 先生成 C01 并确认朱红印章风格，再以它为风格参考，生成 C02—C10 和 D01—D03。
4. 生成 G01，固定熊猫形象，再用它作为 F 类插画中熊猫角色的参考。
5. 生成 B05 后，以它为参考生成 E04，确保实体卡设计与商品图一致。
6. 最后补齐其他 UI 参考、商品图与插画。每次生成一个编号，不让模型把多张素材合成一张拼图。

建议首批为 23 张：A02、B01—B05、C01—C05、D01—D03、E01—E05、F01、F03、F04、G01。它们已经覆盖主卡视觉、首批地点、AI 示例、全部演示商品、统一熊猫角色与主要空状态。

UI 参考图与原始素材分别保存。不能把 UI 截图裁成几个按钮来开发，也不能把用户积分、名称或动态二维码画死在交子底图上。

## 五 不需要生图的界面元素

下列元素仍然属于完整设计范围，但交给开发 AI 用小程序组件、WXSS、Canvas 或一套一致的图标资源实现，避免再生成一批难以适配的图片：

| 元素 | 开发方式 |
| --- | --- |
| 页面标题、用户交子名称、地点名称、积分、编号、时间 | 原生文字组件，纪念图导出时由 Canvas 绘制 |
| 按钮、输入框、标签、任务卡片、弹窗、进度条、分隔线 | 原生组件与 WXSS |
| 六个预设章位和分页提示 | 代码布局，空章位可用细线圆框或轻量占位图标 |
| 返回、箭头、定位、相机、相册、礼物、积分、时钟、扫码、刷新、关闭、成功、失败图标 | 统一图标系统；需位图时从同一源文件导出 |
| “我的交子 / 任务 / 兑换”入口图标及选中态 | 同一套图标；如使用原生 tabBar，导出本地 PNG，并与全项目导航协调 |
| 动态兑换二维码 | 服务端真实数据与受支持的二维码绘制方案生成，不能用生图模型绘制 |
| 微信小程序码，如后续确实需要 | 使用微信提供的真实小程序码能力，不使用生成式伪码 |
| 等级徽标、来源标签、锁定状态、加载动画 | 代码或统一图标资源；使用相同形状与色板 |
| 真实地点照片、真实用户照片、真实商品照片 | 用户或商家提供；本清单商品图仅用于明确标记的演示 |
| 个人纪念图最终成品 | 程序合成 F06、当前交子、用户印章和真实文字，不为每个用户预先生图 |

本清单不要求另生成整页任务背景、按钮切图、单独积分数字图片或假地图。它们会增加资源量，也不利于小程序交互。

## 六 用户照片实时制章的提示词模板

本节是后续开发时调用识别与生图 API 的模板，与上面 39 张静态图片分开使用。用户照片由用户主动选择，服务端执行调用，AI 结果不触发任何积分奖励。

### 6.1 识别模板

```text
请观察用户提供的旅行照片，提取最适合转为简洁印章的一个主要主体。允许类别为 building、food、portrait、object、landscape。只描述可见内容，不推断照片拍摄地点、用户身份、消费事实或是否完成打卡；不能据此授予官方地标认证。建筑名称不确定时，使用“街边建筑”等概括名称。
只输出 JSON，字段为 category、subjectName、visualDescription、suggestedTitle、needsConfirmation。visualDescription 用一到两句话描述可见轮廓与特征；suggestedTitle 不超过 12 个汉字；识别不确定时 needsConfirmation 为 true。将用户确认后的主体与标题用于下一步创作，用户可以修改。
```

### 6.2 根据照片生成个人章

```text
输入图 1 是用户主动提供的旅行照片，作为主体参考；输入图 2 如有，是本项目已经确认的朱红圆章风格参考。
用户确认主体：{{subjectName}}
用户确认描述：{{visualDescription}}
请把照片中的这个主体转化为一枚可叠加到纸质交子背景上的个人纪念印章。输出正方形 1024×1024，真正透明背景，单一朱红 #B83A32，圆形细边框，中粗且简洁的线条，少量印泥肌理，四周约 10% 留白。保留主体可辨认的外轮廓，简化杂乱背景；建筑突出屋顶和立面，美食突出器皿与食物轮廓，人物采用简洁插画或剪影。只生成图案，不生成任何中文、字母、数字、标题、品牌、水印、白色底块或摄影阴影。不要额外增加人物、地标或消费凭证。名称与自制标签由小程序叠加。若不能输出透明背景，则输出无阴影纯白背景，供后续抠图，不画棋盘格。
```

### 6.3 样式修正模板

```text
以刚才的印章为编辑对象，只修正样式：保持主体身份、轮廓和构图不变，统一成单一朱红 #B83A32，增强主要轮廓，减少细碎纹理，保持圆形外框、四周透明边距和真正透明背景。删除文字、白底与阴影，不增加新元素。让它缩小到手机印章尺寸时仍清楚。
```

## 七 生图验收与开发接入

- 交子底图：四个阶段的比例、留白和轮廓一致；无预盖章、错字、积分和二维码。生图模型不保证像素位置完全一致，发现边框漂移时，以 B01 锁定公共底图，只提取其他阶段的边框装饰层，保证印章坐标不动。
- 地标章和自制章：透明边缘干净、风格统一、主图不出界；缩小后能辨认，不残留白方块和棋盘格。
- 地标准确性：使用真实地点参考图检查主要建筑特征，不能仅凭提示词把概括插画当作精确建筑记录。
- 商品图：统一背景与光线，没有文字价格，边缘完整；真实商品确定后，用真实照片替换演示图。
- 熊猫角色：空状态、制章引导和解锁插画使用同一角色，优先用 G01 作为参考；应用图标需团队确认后使用。
- UI 参考：按小程序组件重建布局，适配微信顶部和底部区域；图中文字、伪状态及画面比例不替代真实实现。
- 小程序运行素材：由开发者裁切、压缩并按统一文件名导入 `miniprogram/assets/` 或团队指定资源服务；保留原始文件作为设计源，不把 39 张原图全部直接打入主包。
- 实体卡源图：后续制作前需要按实际厂家模板重新排版文字、印刷尺寸、出血与色彩，不能直接将商品摆拍图作为印刷稿。
