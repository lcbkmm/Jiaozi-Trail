# 春熙路游戏流程与个人中心

地图以真实春熙路道路和建筑轮廓为底，接入完整路线工坊和数字交子。新增的旅人、体验站和个人中心负责把原有能力连起来，完整交子的五个视图、六款票图及原有业务仍可进入。

## 启动与试玩顺序

在仓库根目录运行 `./start-preview.ps1`，待 HTTP 检查通过后打开 [春熙路街区](http://127.0.0.1:8765/baidu-map.html)。脚本复用已有服务或启动后台预览；停止服务或机器重启后重跑。首次数字交子构建与规划服务依赖分别见 [数字交子接入](digital-jiaozi-integration.md) 和 [路线模块接入](module-a-integration.md)。请使用项目预览服务，不要另外启动普通 `http.server`。

1. 点击个人名片，在“我的旅人 → 我的装扮”选择昵称、发型和配色，或拍照/上传制作本机卡通头像，确认应用后查看地图角色。
2. 打开路线工坊，通过完整条件表单、主题预填或本地“整理我的想法”生成方案；先预览，再明确保存、选择和开始。
3. 查看地图内的真实步行路段。范围外的地点保留在完整行程中，不会被挪进春熙路模型；跨出再进入的线路不会用假直线连接。巡航只模拟选中的一段连续板块内线路。
4. 在已开始行程中单独确认位置和完成进度。地图角色移动及地点点亮均不充当真实到店记录。
5. 打开“街角有交子”，选择体验站，点击“模拟商家发放”，阅读并确认后，查看真实写入的试玩到访和交子流水。
6. 在个人中心查看钱包、到访与礼品。兑换需明确确认扣除交子，待领取记录可试玩领取或取消退回；完整数字交子中仍可制作照片记忆、旅程快照和 NFC 纪念网址。

各操作的含义有明确区分：

| 操作 | 保存什么 | 对钱包与行程的影响 |
| --- | --- | --- |
| 点亮地点 | 本机地图探索收藏 | 金色标记，后续发现巡航略过；不发交子、不完成行程 |
| 模拟巡航 | 角色沿所选缓存道路移动 | 不核验 GPS，不自动打卡或奖励 |
| 行程确认进度 | 原规划服务的连续完成前缀、累计步行和消费 | 更新行程与风险；不发交子 |
| 六景演示领取 | 原数字交子的地标收藏 | 沿用原活动首次领取规则，进入同一钱包 |
| 体验站试玩发放 | 商家、旅程、北京时间日期与试玩来源 | 每站每日一次，实际入账 10 枚；不自动完成规划进度 |
| 礼品兑换 | 原交子模块的兑换单和消费流水 | 同一钱包扣款；取消待领取订单时退回，已完成订单不能再次退回 |

## 统一账本与体验站

IFS、太古里西入口、四川特产和烤匠 IFS 的体验站定位取自当前场景的真实 POI。站点是本机测试体验，未表示商家合作、现场验证或正式发放。

个人中心、完整数字交子和地图角标通过同源桥读取 `digital-jiaozi` 的 IndexedDB，不另设地图积分。试玩发放在同一事务内保存事件、到访、钱包与流水；北京时间日期按 UTC+8 计算。数据库以活动、商家、日期约束每日唯一，重复请求不会再次奖励。重试沿用原事件编号，系统会核对事件内容；界面以返回的实际入账回执显示结果，不在响应未知时自行增加余额。

已开始的当前保存路线与当前选择一致时，试玩到访可以关联该路线及旅程；只预览候选、选择了其他路线或没有当前路线时，不会把到访错误写到另一条行程。旅程快照为只读纪念，不会继续写入打卡。

个人中心分为“我的旅人、交子钱包、到访记录、旅途礼品”。到访合并展示六景收藏与商家试玩并去重；示例档案仍独立，不会覆盖地图的个人试玩钱包。账本未同步时显示未知状态，不用零余额或虚构成功代替。

当前礼品目录沿用数字交子规则：20 枚胸章/小挂件、30 枚普通主题冰箱贴、40 枚纪念小物、50 枚熊猫玩偶、60 枚 NFC 实体纪念交子冰箱贴。兑换先确认，待领取订单可“试玩领取”或“取消并退回”；退款与消费共用同一账本。目前没有实际库存、物流、商家结算或正式核销，试玩余额与订单不可作为线下兑换凭证。

## 照片头像与三维旅人

`game-map-avatar.mjs` 构建程序化三维卡通角色：平滑头部和四肢、眼睛高光、腮红、外套衣领和口袋、背包、鞋带以及行走动作。`game-map-avatar-editor.mjs` 负责昵称、两种发型、肤色/发色/衣服等配色和照片草稿。

照片来自前置摄像头或 JPG/PNG/WebP 上传，限制为 12 MB、4000 万像素以内。可调整裁切、缩放与位置；处理过程在本机完成边缘保留平滑和颜色简化，生成 256×256 头像，再贴在三维角色弯曲的面部区域。编辑器本身是二维头像与配色预览，不是三维实时预览。个人资料仅保存处理后的小头像，不保存原始照片；不上传外部服务。

这是照片滤镜和预设三维卡通模板的组合，不是 AI 生成人物、身份识别或单张照片三维重建。需要更接近参考插画的生成式相貌或专属全身模型时，仍需另接合适的图像/三维服务及资产流程，当前实现不会声称已经具备这些能力。

拍照依赖浏览器摄像头权限及安全来源，本机 `127.0.0.1`/`localhost` 可用于开发；远程部署需 HTTPS。拒绝拍照仍可上传。关闭、取消或销毁编辑器时停止摄像头，迟到的授权结果也会释放；取消不覆盖已应用的人物。角色资料保存在当前来源的浏览器本地存储，存储不可用时当次编辑仍可使用，但不能保证刷新后保留。

## 路线工坊与完整交子

路线工坊保留 `module-a` 的完整条件、地点与活动、保存/收藏/历史、位置确认、连续进度、动态演示事件、风险评估和保留已完成部分的剩余重排。更换剩余路线需查看差异并明确接受原 proposal，主题按钮和本地整理只负责填入草稿，不会自动执行规划或接受方案。

未配置语言模型时，前端仍可用明确的本地句式整理预算、总时长、必去/排除、兴趣、步行和排队上限。例如：“预算150元，逛两小时，保留IFS，不吃火锅，少走路，步行上限2公里，排队不超过10分钟”。出现未知句子、未知地点或复杂饮食/无障碍等条件时，整段不应用，并提示在完整表单中调整；不把这些规则称为模型自由对话。真实模型配置及原结构化接口保持可用，未配置时服务端明确报错。

完整数字交子仍保留我的交子、地标收藏、积分兑换、旅程纪念、照片记忆五个视图；领取、原图、照片裁剪/旋转/效果/PNG 导出、旅程快照、独立示例档案、NFC 网址与本机标签绑定继续由原模块处理。IFS 和太古里西入口可返回地图；其他四个地标仍能收藏，但不会伪造春熙路位置。关闭交子窗口只隐藏常驻 iframe，保留原页面及未完成的照片编辑。

## 数据与验证边界

所有本机记录按浏览器来源保存。`127.0.0.1` 与 `localhost`、不同端口均各自隔离；更换地址不会自动迁移，清理浏览器数据会清除记录。纪念网址只引用当前来源的数据，不会跨设备同步；真实手机 NFC 使用需固定 HTTPS 部署及相应数据方案。

当前范围约 1km²，仅包含太古里西入口，不包含完整太古里与大慈寺。道路、楼体、地点和步行线路来自已下载快照；营业、排队、活动、福利和试玩业务不代表实时商家状态。

自动检查覆盖角色资料与滤镜、资源释放、同源桥与异步响应、钱包一致性、试玩幂等、兑换与退回、个人中心、完整规划及本地整理等行为。真实摄像头画面、角色观感、地图穿模、阴影和帧率仍需在实际 WebGL 浏览器上验证，DOM/渲染器替身测试不作视觉验收。
