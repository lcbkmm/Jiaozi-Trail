## 二、当前真实状态

项目是 Vite + TypeScript 手机网页，有五个主页面、浏览器 IndexedDB 数据层、独立模块挂载接口，以及可实际调用供应商的 AI 生图 Node 中转。现有功能不是静态原型。

但默认入口 `src/main.ts` 目前直接执行 `mountDigitalJiaozi(root)`，没有接入宿主适配器；演示领取默认可见。`src/ui/app.ts` 还包含“从这里开始演示”“演示打卡领取”“正式打卡尚未接入”、示例路线、游客自行“演示确认领取”及本机标签配置表单。这些仍是功能验证界面。

仅把 `allowDemo` 设为 `false` 不足以完成任务：部分示例入口和说明依然无条件展示，真实业务也不会因此自动接通。请完成实际游客流程、页面组织、能力状态判断与交互反馈，不要只替换文案或隐藏几个按钮。

## 三、必须交付的游客界面

请自行完成统一的移动端产品设计和页面实现，合理复用现有素材与代码。目标是让首次打开的游客理解：在哪里收藏交子、如何制作照片纪念、怎样找回自己的旅程。

1. **默认入口**：运行 `npm run dev` 后，`http://localhost:5188/#/digital-jiaozi` 直接进入游客界面。生产构建使用同一套入口。不能新建一个无人使用的新页面，然后仍把旧 Demo 作为默认首页。
2. **我的交子**：突出个人地图纪念、已收藏进度和下一步操作。新用户使用真实空状态；回访用户展示已有记录，不默认填入示例收藏或积分。
3. **地标收藏**：使用现有六张正式地标票图，完整展示比例，做好未领取、已收藏、查看详情和领取结果。接入宿主后从实际打卡结果领取，不能让游客点击按钮就被认定为真实到访。
4. **积分兑换**：展示真实本地余额、累计获得、礼品规则与记录。能否提交兑换、取消、查看凭证或领取状态，要按实际服务能力判断。未接入真实兑换服务时展示清楚的“暂未开放”等状态，不扣积分后伪装真实订单；游客不能自行执行工作人员核销。真实积分、库存和核销的可信校验属于正式后端，不能仅靠隐藏按钮宣称已经解决。
5. **照片记忆**：保留并优化“上传照片 → 一键生成珐琅冰箱贴”的主流程。游客不用填写类别、主体、地点、年份、标题和颜色。保留相册/拍照、草稿与作品库、真实生成原图预览/下载，以及可选的纪念海报。
6. **旅程纪念**：保存、历史回看、导出与分享纪念网址符合游客使用习惯。默认页面不要求游客理解 `journeyId`、`tagId`、origin 或手动配置标签。技术配置移至独立开发/工作人员入口；保留必要、简明的本地保存提示。
7. **NFC 入口**：继续支持打开 URL 后恢复本地旅程。通用入口恢复最近已存快照，明确指定但找不到的记录显示正确空状态。保留同设备、同浏览器、同网站的限制，不虚构跨设备恢复。
8. **本地照片贴片**：旧裁剪、旋转、彩色/单色/线条工具继续可用，作为次级功能，不混同为 AI 生图。保留地图照片页和纪念图导出。

默认游客页面不出现“宿主”“适配器”“测试”“重置示例”“素材待交付”等开发说明。不把必要的数据限制和真实业务状态一并删掉。加载、空数据、错误、不可用、重试和成功状态都要完整，按钮名称表达游客能做的事情。

保持六款数字地标票、积分兑换实体礼品、个人 AI 珐琅作品三者的区别，不能互相冒充或自动替换。

## 四、演示与真实业务必须分开

- 正常入口默认关闭演示功能。示例数据、模拟打卡、示例路线、模拟兑换及重置，只能出现在明确隔离的开发演示模式。
- 不能通过随意添加查询参数，就让默认游客模式重新暴露模拟打卡或演示确认领取。界面和动作分发都应检查模式；隐藏按钮本身不提供可信业务校验。
- 个人档案、示例档案继续分库，示例重置不能删除个人记录。
- 不清空、偷偷重置或丢弃已有 IndexedDB 数据。历史 `source: demo` 记录不能改写成真实到访；如需迁移，保留来源并说明方案，避免旧演示积分被当作正式可信余额。
- 查看现有仓库是否有真实路线、打卡、兑换接口。已有则按明确协议接入；没有则完善模块内能力接口、不可用状态和接入说明，明确列出需要队友提供的字段及回调，不臆造一个“调用成功”的服务。
- 接口缺失不应阻止完成全部游客界面，以及现有照片、AI 创作、个人纪念等真实可用流程。最终分别报告已实际可用、已完成界面但待外部接入的内容。
