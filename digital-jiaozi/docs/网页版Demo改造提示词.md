二、最新产品规则：彻底取消交子升级

下面规则替代旧版关于微信小程序、服务器保存个人旅程、等级和旧积分表的规定。旧总体方案、旧生图文档仅作历史参考，不能把旧要求重新引入程序。

1. 地图交子：开始是一张没有到访图案的交子底图。每次获得新的地标交子，就把相应地标图案添加到地图交子上，保存到访时间与顺序。保留竖版主展示、两列三行的自动布局思路；根据新图案实际比例调整，图案应足够大、清晰，不机械套用旧单色圆章的尺寸。
2. 地标交子：本期共六款，每款对应一个不同地标，属于平等的收藏纪念票，不是等级、稀有度或升级阶段。六个地标尚未最终确定。先用稳定的 landmark-01 至 landmark-06 内部编号和“示意地标 01”等占位名称，不自行宣布已选定六个真实地标。
3. 同一浏览器本地档案、同一活动、同一地标首次有效打卡，只领取一次地标交子、获得一次积分、向地图添加一次图案。事件重放、重复点击、刷新重试都不能重复奖励；仅靠 eventId 去重不够，还要按活动与地标做业务去重。
4. 六款每款默认奖励 10 分，本期地标奖励总上限 60 分。开始时余额为 0；不再执行旧版领取、签到、消费、文化任务、路线完成的加分，也不保留旧的 100/300/600 分等级及“600 分解锁、再花 200 分”的门槛。
5. 同时记录累计获得积分与当前可用积分，累计积分只用于解释获得记录，不决定等级。兑换只扣可用余额，不删除收藏票、不移除地图图案、不抹掉历史旅程；退款不重复增加累计获得积分。
6. 礼品默认集中配置为：20 分胸章/小挂件、30 分普通主题冰箱贴、40 分纪念小物、50 分熊猫玩偶、60 分 NFC 实体纪念交子冰箱贴。这是 Demo 规则，不是真实采购价格或实物库存承诺，后续可以修改配置。
7. 兑换采用余额消费制，不是集齐两张、三张、五张就分别免费领奖。界面展示全部兑换选择及兑换后的余额，让用户知道花掉积分会影响其他礼品的兑换。
8. 实体纪念交子是固定设计的 NFC 冰箱贴，保留独立礼品展示与回看入口，不作为地图交子升级后的形态。
9. 原有用户照片自制图案可以继续保留，表达个人记忆，不奖励积分，不认定为真实地标打卡。不要为本次改版强制所有图案变成单色圆章。

清理所有用户可见的旧等级名称、升级进度、升级动画、纪念版解锁文案、旧兑换门槛，以及实际执行旧规则的代码路径。不要只换文案却继续运行旧计算逻辑。

三、个人数据保存于浏览器本地

- 旅程、已领取地标交子、地图元素、积分流水、兑换记录、照片成品使用 IndexedDB 持久化；图片保存 Blob，而不是把大量 Base64 塞进 localStorage。localStorage 仅用于少量设置或启动索引。
- 数据模型至少区分本地档案、活动、旅程、稳定地标编号、领取记录、积分流水、兑换记录和媒体资源。不要把显示名称或数组下标当作唯一业务标识。
- 通过统一 repository/store 处理业务，页面不各自读写互相矛盾的数据副本。领取交子、记录到访图案、奖励积分须在同一事务中完成；兑换记录和扣分也须原子提交，失败不能只写一半。
- 同一请求重复执行不得多次扣分或发奖；余额不能为负。对多标签页操作，利用 IndexedDB 事务和唯一约束保证去重与余额一致，不只依赖单个按钮的 loading 状态。
- 若原程序支持取消兑换，可保留“待领取取消后原额退回一次”。完成领取后不能再退款，不为本轮新增复杂的动态兑换码服务器或工作人员权限系统。
- 本地模式只演示本机领取、积分和兑换，不宣称实现了可信定位、防篡改积分、全局库存或跨设备核销。库存若保留，标为演示库存；领取确认标为演示确认。
- 在网页中适当说明“记录保存在当前浏览器”。更换设备、浏览器、用户配置文件、网站域名或清除网站数据，不会自动恢复原记录；不提供虚假的云同步成功提示。
- 图片与路线不上传到个人旅程数据库；核心流程不依赖后端数据库、微信登录或服务端会话。已有可选 AI 服务不属于个人旅程的云同步功能。
- 如发现旧版本地数据，先识别版本并保留备份/旧档案，再做明确迁移。不能静默清空用户记录，也不能把旧的数百积分直接当作新六地标活动余额。可将旧活动归档、新活动使用新规则；未知地点不猜测映射到六个新地标。
- Demo 示例数据与用户自己的记录必须隔离；“重置示例”不能清空个人照片和实际旅程。不要为了展示效果每次启动都覆盖本地数据。

四、NFC 打开网页与旅程回看

用户已经用手机实测 NFC 可以打开网址。本轮无需做网页读取 NFC 的功能，不引入 Web NFC、微信 JS-SDK 或小程序跳转作为前置条件。NFC 标签负责让系统浏览器打开网站，网页负责读取本地记录。

- 提供可直接进入旅程纪念页的稳定网址入口；沿用现有路由方案，无约定时可用兼容静态部署的 hash 路由。明确部署子路径、base 配置及直接打开深链接的处理，不能只在站内点击时正常。
- URL 可携带 journeyId，或使用 tagId 在本机映射到已保存旅程；只有本机确实存在对应记录时才展示。NFC 中不写入完整路线、照片或 API 密钥。
- 无指定记录的通用入口可展示最近保存的旅程或让用户选择。指定了某个旅程/标签却查不到时，说明“当前浏览器暂无这段旅程”，不能悄悄替换成另一段旅程并冒充原记录。
- 回看页展示那次实际保存的路线、实际到访地点、当时的地图交子、收藏票和照片。保存必要的路线与地点展示快照，不只存一个可能变化或失效的 routeId。
- 初次进入、尚未保存旅程、未知链接参数、旧数据版本等状态均有明确反馈。允许主动进入标注清楚的“示例旅程”，示例不冒充当前用户的历史。
- tagId 的绑定仅是本地演示映射，不宣称全网绑定、身份认证或换手机可恢复个人记录。
- 使用相对或可配置的网站地址，不把开发电脑的 localhost、本机磁盘路径、易失效的临时隧道地址写成正式 NFC 入口。README 中说明正式部署后如何取得和写入最终 HTTPS 网址；实际写卡不作为编码完成的前提。
- 验证通过直接打开同一路由能恢复本地旅程，并说明真实手机碰 NFC 这一项是否实际测试。桌面手动打开 URL 只能证明网页入口行为，不能写成手机 NFC 实测通过。

五、六张正式图片还没完成：现在如何开发

- 建立集中式 landmark/asset manifest，六条记录包含稳定内部编号、可配置的正式 placeId、显示名称、主色、主图来源、占位状态，以及地图图案的显示方式。正式地名未确认时 placeId 可以为空，Demo 事件使用内部编号。
- 六款先用有区分度的彩色插画式占位图或程序绘制图形，明确标为“示意”。不用六张完全相同的灰框，也不强制统一朱红、圆形印章、透明底。
- 真实图片可为 PNG/JPEG/WebP；在收藏列表、票面详情和地图中清晰展示。票面完整图使用合适的 contain/留白；地图可以复用同图的主体裁切或缩略显示，不把细字票面缩得无法辨认，也不拉伸、不切掉主要建筑。
- 地名、日期、编号、积分等文字由网页绘制，不能依赖生图准确生成文字；不能让图片里可能出现的“10”等文字决定业务分值。
- 地图底图、票面、实体礼品展示、用户照片分层处理。没有新底图时用代码绘制暖纸纹理和交子边框，不额外要求生成六张地图图案才能开工。
- 页面展示与 Canvas 导出共享布局数据。素材缺失或加载失败时有回退；不能一张图失败就导致整页白屏或无法保存纪念图。运行时不引用 D:\... 本机路径或直接依赖 assets-source/ 原始大图。
- 素材替换通过 manifest 和约定目录完成，不修改积分、打卡或兑换代码。提供说明：六张图各放哪里、改哪些配置、如何压缩、如何检查真实图片已加载。地图展示需要的裁切可通过配置完成，不要求生成端另做六张新图。
- 不操作 WorkBuddy/Flova，不更改其权限，不删除、覆盖、批量提交生成端正在写入的图片、素材映射与回执。

复用现有组件和导航，至少贯通以下页面或视图，不要求为每项新建一个路由：

2. 地标收藏：六张地标票的已获得/未获得状态、详情、到访时间；演示打卡入口与正式宿主打卡跳转区分。
3. 兑换中心与记录：可兑换礼品、所需积分、兑换后余额、确认结果与本地记录，明确为 Demo。
4. 旅程纪念页：可被 NFC URL 直接打开，恢复指定或最近保存的本地旅程，处理无记录情况。
5. 已完成的照片图案功能：保留上传/拍照、实际裁剪和从本次照片生成图案、保存与地图展示。允许彩色照片贴片或原有可用处理模式，不继续把纯单色圆章当唯一规范。

八、实现顺序与验证

按现有工程调整以下顺序，不因等待地标图片或可选 AI 而停工：

1. 先跑通 Web 启动与模块入口，移除升级体系和旧积分执行路径，建立新规则配置。
2. 贯通首次打卡→领取地标票→添加地图图案→积分入账→刷新恢复。
3. 贯通积分兑换→扣分与记录→刷新恢复，保留收藏和地图。
4. 贯通保存旅程→关闭再打开 NFC 对应网址→恢复本地纪念页。
5. 复用原有照片处理与导出，完善彩色占位、移动端布局和素材替换说明。

对关键业务编写并运行必要测试，界面以真实操作验证为主，不为每个样式添加镜像测试。至少验证：

- 初始 0 分，首次地标打卡后 10 分、1 张收藏、1 个地图图案；刷新后不变。
- 同一事件重放、同地点换 eventId 重放、快速重复点击都仍为 10 分和 1 张票；多标签页并发不重复发奖。
- 六个不同地标共 60 分、6 张票；兑换 20 分礼品后余额 40，累计获得仍 60，收藏和地图均保持 6。
- 同一个兑换请求重试不重复扣分；余额不足无法兑换。若保留取消，退款只发生一次且不增加累计积分。
- 另一独立测试场景中，60 分兑换 NFC 礼品后余额为 0，旅行记忆仍完整。
- 本地照片 Blob、地图、流水和旅程在页面关闭后重开仍可恢复；资源丢失或存储失败时反馈真实原因，不假装保存成功。
- 直接打开带旅程参数的纪念页可恢复正确记录；无记录时进入空状态，示例旅程与个人数据互不污染。
- 六张真实图都没有时没有破图；至少替换一份测试素材后可以确认 manifest 生效，导出纪念图仍可用。
- 375px/常见手机宽度下图案、文字和按钮可读可操作，页面不横向溢出，底部操作区不会遮住内容。
- 完成项目实际提供的类型检查、测试与生产构建，再用浏览器实际走一遍主要流程。没有可用浏览器/真机时如实记录未验证项，不能用构建通过代替交互或 NFC 测试通过。
