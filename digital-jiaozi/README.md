# 数字交子模块

负责人：熊俊豪。

本目录用于独立开发数字交子板块。模块与 AI 逛吃路线共用 Jiaozi-Trail 仓库，通过独立目录和开发分支管理，完成联调后再合并到主分支。

当前已完成目录与协作准备，以及数字交子模块需求方案，尚无可运行应用。产品范围、积分配置、接口建议与验收要求见 [数字交子模块总体方案](docs/数字交子模块总体方案.md)。开发前仍需对齐团队技术栈和公共接口。

交付平台已确认是微信小程序。图片准备见 [微信小程序图片清单与生图提示词](docs/微信小程序图片清单与生图提示词.md)，包含 UI 参考图、票面、地标章、商品和插画的逐张提示词。

## 模块范围

- 数字交子的领取、展示与成长进度。
- 任务与成就展示、跨店任务完成后的交子变化。
- 交子纹样、纪念卡面与分享展示。
- 权益展示、兑换入口和核销结果展示。

AI 路线生成、商户基础数据、用户身份和公共服务的归属由团队共同确定。本模块优先复用团队公共能力，避免重复开发。

## 联调前需要对齐

- 团队使用的前端框架、后端框架、包管理器与启动方式。
- 用户、活动、门店、任务、交子与权益使用的标识。
- 到店或任务完成事件如何传入，如何查询最新交子状态。
- 成长、权益库存及核销由哪个服务负责校验。
- 数据字段、接口错误信息、身份校验与模拟数据的使用约定。

实际权益由后端规则判定；AI 生成的文字或纹样不直接触发权益发放、库存扣减或核销。模块总体方案已给出比赛原型的积分与兑换初始配置；真实活动库存和实物供给由团队另行确认。

## 开发约定

- 本模块开发分支：`codex/digital-jiaozi`。
- 源码与模块说明优先放在本目录，修改根目录公共配置前先与相关成员对齐。
- 沿用根目录的 Git 仓库，不在模块内再次执行 `git init`。
- 按功能分批提交，提交信息写明改动目的。
- 不提交访问密钥、个人账号凭据、依赖目录或本地产物。
- 技术栈确定后补充安装、启动和验证命令；当前不预设依赖。

## 日常提交

在仓库根目录执行：

```powershell
git switch codex/digital-jiaozi
git status
git add -- digital-jiaozi/
git diff --cached
git commit -m "feat(digital-jiaozi): 描述本次完成的功能"
git push -u origin codex/digital-jiaozi
```

以上提交命令适用于只修改本模块的情况；涉及共享文件时，应先检查并按实际路径单独暂存。

## 同步与合并

开始新一轮开发前，在工作区改动已妥善保存的前提下，执行：

```powershell
git fetch origin
git switch codex/digital-jiaozi
git merge origin/main
```

有冲突时先解决并验证，再继续开发。避免对团队共享分支强制推送。

功能完成后推送模块分支，创建从 `codex/digital-jiaozi` 到 `main` 的 Pull Request，说明改动、启动方式、验证结果及联调依赖。经团队审阅、联调后再合并，不通过手工覆盖文件夹整合代码。
