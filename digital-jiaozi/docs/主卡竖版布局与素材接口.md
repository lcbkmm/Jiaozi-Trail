# 主卡竖版布局与素材接口

2026-10-31：同步原资料分支本地提交 `e10d1ba` 的最新章位决定，替代此前横版主卡。只迁入技术配置，没有合并另一窗口的素材或未跟踪文件。

数字主卡为 2:3、686×1029 rpx，两列三行，每页六章，按收集顺序自动分页。实体纪念卡本体继续横版 3:2。

配置唯一维护源为 `shared/card-layout.json`，`npm run setup` 同步到 `miniprogram/packages/digital-jiaozi/config/card-layout.json`。前端和 Canvas 共同使用分包 `services/card-layout.js`，运行时不读取 docs。业务规则仍放 `shared/rules.json`，旧 `slots` 已移除，避免两套章位。

列 x=0.09/0.55，行 y=0.140/0.385/0.630，单元 w=0.36、h=0.23。名称字号 24 rpx、行高 32 rpx，图文间距 8 rpx，上下内边距各 4 rpx。单元先预留名称和边距，再计算正方章图，章名不会覆盖下一行。具体安全区和素材清单见 [给图片制作 AI 的交接](给图片制作AI的交接.md)。

页面保留完整名称，使用渲染引擎的单行省略；Canvas 用实际 `measureText` 宽度逐字省略，不通过 `fillText` 的 maxWidth 缩字。点击完整单元显示全名和章图，章图可放大。导出为 1200×1800 的完整票面。

B01 目前为 600×900 代码占位；所有等级共用。正式 B01 按 2:3 导入，旧横图不会拉伸或旋转使用。标题、等级、编号、页码和章图由代码叠加；图片缺失时页面组件回退，Canvas 保留底色/边框并逐章回退。

`npm test` 执行实际导出函数并覆盖远程照片、失效回退、分页、中文长名和不同字符宽度；320/375/430 CSS px 屏宽的几何检查确认章名与图案包含在单元内。`npm run qa:images` 生成三种背景的透明度图和三档屏宽的六章合成图，375 屏宽对应 343 px 主卡、章画布约 94.335 px。这些是开发验证，不替代微信运行与真机验收。
